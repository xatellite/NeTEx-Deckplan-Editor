# How to Contribute?

Contributions are what make the open source community such an amazing place to learn, inspire, and create. Any contributions you make are **greatly appreciated**.

If you have a suggestion that would make this project better, please fork the repo and create a pull request. You can also simply open an issue with the tag "enhancement".
If this project brings you any value or inspires you don't forget to give the project a star! Thanks again!

1. Fork the Project
2. Create your Feature Branch (`git checkout -b feature/AmazingFeature`)
3. Commit your Changes (`git commit -m 'Add some AmazingFeature'`)
4. Push to the Branch (`git push origin feature/AmazingFeature`)
5. Open a Pull Request
6. Sign the Contributor License Agreement
7. Comply to our AI contribution guidelines

## The Contributor License Agreement

This Project can only accept original source code from CLA signatories.

The CLA is a legal document in which you state you are entitled to contribute the code and are willing to have it used in distributions and derivative works. This helps us ensure that all code contributions are free from legal encumbrances.

It is important to read and understand this legal agreement.

### How do I sign?

On your first Merge request, we will reach out to you to sign the CLA. You will receive an email from us with instructions on how to sign the CLA.

## AI contribution guidelines

To ensure code quality, this project can only accept code contributions of humans.

By contributing, you agree that:

- You must not submit work that you cannot legally contribute.
- You remain responsible for the correctness, quality, and maintainability of your contributions.
- You must not misrepresent AI-generated content as entirely human-authored work.

### Use of Generative AI

The use of Generative AI tools (such as LLMs, code assistants, and AI writing tools) is permitted, provided that their use is disclosed and documented.

#### AI-Generated Changes to the project

If AI is used to generate or substantially modify code:

- Clearly indicate this in the commit message or merge request description.
- Review, test, and understand all generated code before submission. We might ask specific questions during the review process.
- Record:
  - The model used (including version if known).
  - A summary of how it was used.
  - The prompts or interactions used, or a concise summary of them.

Here is an example:

```
Generate parser tests using ExampleLLM 2.1

Model: ExampleLLM 2.1
Purpose: Generate initial test cases for parser validation.
Prompt summary: Generate tests covering valid and invalid input formats.

Reviewed, corrected, and verified manually before submission.
```

### Transparency

When in doubt, disclose AI use. Transparency helps maintain trust and ensures compliance with our contribution guidelines.

Project maintainers may request additional information about the origin of a contribution if needed.

### Non-Compliance

Contributions that do not comply with these guidelines may be rejected or require revision before being merged.

Thank you for helping keep this project open, transparent, and sustainable.
